# Existing PARA + Zettelkasten hybrids and public vault templates

**Angle 3 of 6.** Scope: proven hybrids, public vault templates, 2025-2026 agent-ready vaults. Evaluated against prototype option D (ROADMAP §1.2; AGENTS.md §2 folder map).

## Executive summary

- No mature hybrid exists with multi-year public evidence. Most "PARA + Zettelkasten" write-ups are blog setups with no long-term reports. Treat all adoption claims as weak.
- The closest proven shape is PARA-lifecycle folders with Zettelkasten notes placed in a Resources layer, projects linking (not containing) knowledge. Option D already has this shape (`40-knowledge` = Resources/Zettel layer).
- Prototype D is not pure lifecycle. `50-meetings`, `60-records`, `70-people` are kind-based folders (option C). That is defensible but must be stated as a rule, otherwise kind lives in two places (folder and `type`).
- Borrow from LYT (MOCs as hubs), Kepano (multi-membership via properties, Bases for views, no nested folders outside projects), and the Karpathy LLM Wiki (generated `index` and append-only `log`). Do not adopt Johnny.Decimal numbering or ACE's Atlas/Calendar/Efforts folders.

## Key findings

1. **Lifecycle folders plus a Resources layer is the common hybrid.** Obsidian Academy, the Reitz essay, and the forum "PARA + Zettel" proposals all put atomic notes in a Resources or Knowledge folder that projects link into. Option D already does this. Source-backed.
2. **Multi-membership is the main pain point of folder hybrids.** Kepano uses properties so one note can sit in several categories without duplication. The forum "ACE" thread reports confusion over where project notes go. D forces one folder per note; a `related` link covers multi-membership, but folder placement is still single-valued. Decision needed (roadmap 1.2 "folders vs properties").
3. **Kind lives in two places in D.** `type` property plus kind folders (`50-meetings`, `60-records`, `70-people`). Agents need one rule. Suggest: folders only for lifecycle and for immutable kinds (`60-records`, `50-meetings`); everything else by property.
4. **Hubs are the consistent success factor.** LYT MOCs, the Karpathy `index.md`, Kepano's category overviews, and the JD index all solve the same problem: a single entry point. D's "every note links a hub" rule is sound; the gap is that the hub set (`project`/`area`/`moc`) has no index note agents read first. Add one generated `Home`/index (Bases view or hand-maintained).
5. **Agent-facing precedent is a schema file plus append-only log.** Reitz (`CLAUDE.md` as contract, no restructuring) and Karpathy (schema, index, log) match AGENTS.md's direction. AGENTS.md lacks an explicit "do not restructure folders" rule and an index. Both are cheap to add.
6. **Numeric schemes (JD, Reitz numbering) help sorting but add cap constraints.** JD's 10-per-level cap is incompatible with 17 types; Reitz's numbering is for visual order only. Keep D's numbered folders only if sort order matters on mobile/file browser; otherwise drop numbers.
7. **Stacking methods is discouraged by the methods' own advocates.** JD forum member advises against PARA + JD. Obsidian forum: Zettel-in-PARA friction. Keep one hybrid shape, not three methods.
8. **Kepano's "no automation" stance conflicts with the owner's AI goal.** Karpathy delegates bookkeeping to the LLM. The vault can serve both only if the human-authored layer (`author: human`, AGENTS §6.2) stays separate from agent-maintained artefacts (index, log, lint).
9. **Bases is core, not a plugin.** Per the Obsidian help page, Bases creates table/list/card/kanban/map views from properties with no community plugin. This matters for the 5-plugin cap. Mobile support and version are not confirmed in the source.

## Adoption risk

- **PARA (Forte):** Mature, widely used since ~2017; community adaptations common. Low abandonment risk; low prescriptiveness on subfolders.
- **ACE / LYT:** One author, 2023 framework; forum shows unresolved structural questions. Medium risk.
- **Kepano vault:** Personal vault, explicitly "in no way dogmatic." Treat as a pattern source, not a spec.
- **Johnny.Decimal:** Commercial products; forum skepticism about PARA stacking. High rigidity.
- **Karpathy LLM Wiki:** Pattern from April 2026; fast-moving. Treat as a pattern; implementations vary.
- **Reitz essay:** Single-author blog, March 2026; recent, unverified over time.
